## Supported path in the pinned SDKs

1. Construct `new DynamicBondingCurveClient(connection, commitment)` ([source](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/0c5e375f1f9764e82d8b59a49698a0748ef8a739/packages/dynamic-bonding-curve/src/client.ts)). `client.partner.createConfig(params)` builds the config transaction; `client.creator.createPool(params)` builds the launch transaction. The [SDK README](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/main/packages/dynamic-bonding-curve/README.md) says config, pool, DBC trading, threshold completion, migration, and DAMM v2 trading are the intended lifecycle. Validate the chosen `ConfigParameters`, supply, fee, quote mint, lock allocation and creation cost with actual SDK validation before signing.
2. DBC `client.pool.swapQuote2({ virtualPool, config, swapBaseForQuote, swapMode: SwapMode.ExactOut, amountOut: BN, currentPoint, hasReferral, eligibleForFirstSwapWithMinFee, slippageBps })` supports an exact-output quote. `client.pool.swap2({ pool, owner, swapBaseForQuote, swapMode: SwapMode.ExactOut, amountOut, maximumAmountIn, referralTokenAccount })` builds the matching transaction. This is [source verified](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/0c5e375f1f9764e82d8b59a49698a0748ef8a739/packages/dynamic-bonding-curve/src/services/pool.ts): the older `swap` is exact-input only. Buy whole credits with base-unit `BN` amounts; cap quote spend using `maximumAmountIn`. Sell whole credits by using base-to-quote exact-input and `minimumAmountOut`. Re-fetch state and re-quote before simulation/signing; actual transaction success and token deltas are authoritative.
3. Read `client.state.getPool`, `getPoolConfig`, and the pool's `poolState.quoteReserve` versus `config.migrationQuoteThreshold`. `getPoolQuoteTokenCurveProgress()` is useful for display, but a rounded progress number alone is not proof of migration. Inspect `poolState.migrationProgress` and the derived DAMM address/account. DBC [state SDK source](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/0c5e375f1f9764e82d8b59a49698a0748ef8a739/packages/dynamic-bonding-curve/src/services/state.ts) and [onchain migration state](https://github.com/MeteoraAg/dynamic-bonding-curve/blob/f552f20aa3c1c7631427c3827aeea7c58b902813/programs/dynamic-bonding-curve/src/instructions/migration/dynamic_amm_v2/migrate_damm_v2_initialize_pool.rs) support these checks.
4. `client.migration.migrateToDammV2({ pool, dammConfig, payer })` returns migration transaction material and derives the DAMM pool from the DAMM config and the two mints ([source](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/0c5e375f1f9764e82d8b59a49698a0748ef8a739/packages/dynamic-bonding-curve/src/services/migration.ts)). The [official README](https://github.com/MeteoraAg/dynamic-bonding-curve-sdk/blob/main/packages/dynamic-bonding-curve/README.md) says Meteora's migrator service normally performs this once the quote reserve reaches the threshold. Do not assume the threshold causes instantaneous migration. Resolve and verify the *actual* DAMM config and pool account; do not guess the pool from mint alone.
5. DAMM v2 SDK 1.4.10 package types expose `new CpAmm(connection)`, `fetchPoolState(pool)`, `getQuote2` and `swap2`, including `SwapMode.ExactOut` and `ExactIn`. They also expose `derivePoolAddress(config, tokenAMint, tokenBMint)`. See [official DAMM v2 guide](https://docs.meteora.ag/developer-guides/damm-v2) and [TypeScript reference](https://docs.meteora.ag/developer-guides/damm-v2/typescript-sdk/reference). Confirm live account ordering, vaults, token programs, fees, and token decimal handling against a migrated pool before enabling this route.

## Supply and pre-migration burns

The current [DBC program source](https://github.com/MeteoraAg/dynamic-bonding-curve/tree/f552f20aa3c1c7631427c3827aeea7c58b902813), inspected at commit `f552f20`, mints the configured initial base supply into the DBC vault and then revokes mint authority during SPL pool initialization ([instruction](https://github.com/MeteoraAg/dynamic-bonding-curve/blob/f552f20aa3c1c7631427c3827aeea7c58b902813/programs/dynamic-bonding-curve/src/instructions/initialize_pool/ix_initialize_virtual_pool_with_spl_token.rs)). `fixed_token_supply_flag` chooses the configured pre-migration supply as that initial amount ([config source](https://github.com/MeteoraAg/dynamic-bonding-curve/blob/f552f20aa3c1c7631427c3827aeea7c58b902813/programs/dynamic-bonding-curve/src/state/config.rs)). Verify the created mint's `mintAuthority == null` and its actual freeze authority onchain; metadata immutability is a separate property.

The swap completion check uses the **DBC base vault balance**, migration base threshold, accrued fees, and vesting amounts ([swap source](https://github.com/MeteoraAg/dynamic-bonding-curve/blob/f552f20aa3c1c7631427c3827aeea7c58b902813/programs/dynamic-bonding-curve/src/instructions/swap/process_swap.rs)). DAMM migration uses the DBC vault amounts and burns eligible leftover inventory; no check of the global mint supply was found in the inspected migration and swap paths ([migration source](https://github.com/MeteoraAg/dynamic-bonding-curve/blob/f552f20aa3c1c7631427c3827aeea7c58b902813/programs/dynamic-bonding-curve/src/instructions/migration/dynamic_amm_v2/migrate_damm_v2_initialize_pool.rs)). **Inference:** burning a customer's already purchased tokens outside the vault should not alter these reserve checks. **Fixture-verified on 2026-09-24:** the full Meteora create, buy, external burn, graduation, migration, DAMM trade and external burn sequence passed on a local validator. This is not WORKDROP Anchor redemption or a deployed pilot. A holder burn reduces actual global supply below the configured cap; the accounting must use observed supply and completion records.

## Configuration and economics cautions

- The DBC [overview](https://docs.meteora.ag/core-products/dbc/what-is-dbc) and [launch configuration guide](https://docs.meteora.ag/core-products/dbc/launch-configurations) distinguish fixed supply, migration inventory, leftover receiver, trading fees, protocol fees and migration fees. The full pre-migration supply, including DBC inventory and future DAMM inventory, is potential service liability. DBC quote reserve is liquidity, not provider revenue.
- New DBC 1.5.12 configs cannot choose DAMM v1 or the deprecated rate limiter. The SDK's 1.5.12 changelog says quote mints outside the permissionless set need a token badge. Do not assume a specific stablecoin or Token-2022 quote mint works before checking badge requirements and devnet availability.
- The SDK exposes creator trading-fee claim and creator migration-fee withdrawal builders; prove fee flow with actual pre/post balances and claim transactions before listing fees as operating cash. Migration may leave unsold base inventory or burn part of it according to the selected fixed-supply configuration. Do not treat `preMigrationTokenSupply` as circulating supply.
- [Meteora's sample config](https://github.com/MeteoraAg/meteora-invent/blob/main/studio/config/dbc_config.jsonc) is illustrative; its migration percentage and threshold are not suitable pilot values without a supply, liquidity, fees, and fulfillment calculation.
