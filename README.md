# WORKDROP

**Launch your AI's next 100 creations. Let people use them or trade them.**

WORKDROP's first prototype is deliberately smaller: a 12-credit local pilot for one precisely defined 15-second product teaser. Each whole credit covers one complete render. The current app has a working CPU renderer, durable local two-wallet ledger, four-artifact scenario, and responsive customer UI. **The customer app's trades are simulations. No WORKDROP mint, pilot Meteora pool, Anchor redemption, or mainnet deployment has been verified.** A separate real-program local validator test proved a Meteora DBC buy, external burn, graduation, DAMM migration, and later buy/burn using fixture programs. The Anchor program compiles but is not deployed or wired to the app. Do not use this version with real funds.

## Quickest successful run

Requirements: Python 3.11+, Node 20+, FFmpeg and ffprobe in `PATH`.

```powershell
python -m pip install -r requirements.txt
cd web
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

In a second terminal from the repository root:

```powershell
python -m uvicorn app.server:app --host 127.0.0.1 --port 8000
```

Open <http://127.0.0.1:5173>. The local database is created at `data/workdrop.sqlite3`. Use the header to switch between **demo wallet A** and **demo wallet B**. Buy, create, sell, and buy again through the clearly labeled local market. Job videos render on CPU and appear after validation and settlement. The featured MP4 is already in `assets/sample/`.

To generate a fresh, reproducible four-video 10/3/7/1 story without modifying the UI database:

```powershell
$env:WORKDROP_DATA_DIR='data/demo-fresh'
python -m scripts.demo
```

Use a new directory for every run. To inspect that demonstration in the UI, start the API with the same `WORKDROP_DATA_DIR`. The script reports artifact paths and reconciled balances. These are **builder-operated demo wallets and local ledger events**, not independent traction or onchain transactions.

For the full browser walkthrough on a fresh local database, install `requirements-qa.txt`, run `python -m playwright install chromium`, start both services with a new `WORKDROP_DATA_DIR`, then run `python -m scripts.browser_qa`. It drives the buy/use/sell/second-wallet path, checks four private MP4s and the 0/6/2/4 reconciliation, and saves a final screenshot.

The API starts a small in-process render queue for the quickest run. For a separate local worker, run `python -m scripts.worker` with the same `WORKDROP_DATA_DIR`; SQLite leases prevent it from claiming a job that another worker owns. Run `python -m scripts.reconcile` to print the base-unit reconciliation.

## Checks

```powershell
python -m unittest discover -s tests -v
cd web
corepack pnpm build
cd ..
cargo check -p workdrop_entitlement
```

`python -m scripts.make_sample` regenerates the original sample input and MP4. The renderer invokes FFmpeg with argument arrays, probes codec, pixel format, 1920×1080 dimensions, 30 FPS, 450 frames, and 15.0 seconds (50 ms container tolerance). It stores a SHA-256 hash and render metadata per customer job. The shipped sample was generated on an Intel Xeon E5-2678 v3 Windows host with FFmpeg 8.1.1 and Pillow 12.2.0. A measured render took 9.39 seconds after the screenshot-motion optimization; timing depends on hardware and concurrent load. Re-run the benchmark on deployment hardware.
